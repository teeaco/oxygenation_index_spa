# Лабораторная 8

## Цель работы

Внедрение адаптивности и развертывание приложения.

## Порядок показа

1. Открыть GitHub Pages с mock-данными на телефоне и сохранить PWA.
2. Открыть PWA, применить фильтрацию услуг, перейти на страницу Подробнее и вернуться, чтобы показать старое значение фильтра.
3. Перейти в адаптивный режим браузера и поменять ширину.
4. Объяснить в коде настройки размера карточек, количества колонок и других адаптивных параметров.
5. Открыть GitHub Pages на компьютере и продемонстрировать работу с бэкендом.
6. Показать работу с бэкендом в собранном Tauri-приложении, не в dev-режиме.
7. На компьютере показать подключение к бэкенду по IP локальной сети, не через localhost.
8. Сравнить IP сервера из консоли и в коде приложения.
9. Через Wireshark или tcpdump найти порт Tauri-приложения.
10. Отредактировать услуги в БД и продемонстрировать изменение в Tauri.
11. Показать HTTPS в локально развернутом фронтенде.

## Контрольные вопросы

- Flux.
- Схема Redux: store, reducer, dispatch, action.
- Виды нативных приложений: PWA, Tauri и другие.
- GitHub Pages.

## Диаграммы

- Deployment-диаграмма: все узлы и компоненты системы, включая фронтенд, web-сервер со статикой, веб-сервис, базу данных и другие хранилища. Узлы соединить протоколами, компоненты фронтенда и бэкенда поместить в узлах, указать API между ними.
- Диаграмма состояний для статусов заявок.
- Диаграмма прецедентов интерфейса React.

## Задание

Внедрить менеджер состояний для хранения значений фильтров, добавить адаптивность и PWA, создать Tauri-приложение и развернуть приложение на GitHub Pages.

Добавить Redux Toolkit для хранения фильтра услуг. Рекомендуется использовать расширение браузера Redux DevTools.

Развернуть фронтенд на GitHub Pages и добавить возможность работы в режиме PWA.

Добавить адаптивность для трех страниц приложения.

Создать простое нативное приложение на Tauri для интерфейса гостя без авторизации и редактирования. Приложение должно состоять из трех страниц с фильтрацией и картинками.

Подключить Tauri-приложение к разработанному API через IP-адрес в локальной сети, не через localhost.
