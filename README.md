# Лабораторная 7

## Цель работы

Завершение интерфейса пользователя в React.

## Порядок показа

1. Показать авторизацию, добавление в заявку и просмотр заявки.
2. Показать, что URL назван по теме, а черновик открывается по id.
3. Показать отдельные кнопки для всех пяти методов изменения заявки и м-м.
4. Показать формирование заявки в режиме разработчика.
5. Показать страницу списка заявок с диапазоном даты формирования за сегодня.
6. Обновить страницу по F5 в состояние гостя Redux и в Application показать, что JWT или сессия остались.
7. Использовать содержимое localStorage или cookie из Application, чтобы показать заявки пользователя в Insomnia или Postman.
8. Показать в коде все состояния Redux.
9. Показать axios в кодогенерации.
10. Показать применение сгенерированного фронтенд-кода из Swagger в thunk и что методы названы по теме.

## Контрольные вопросы

- Схема Redux Toolkit: reducer, store, middleware.
- useContext.
- axios.
- localStorage.

## Диаграмма

Activity-диаграмма или BPMN для итогового бизнес-процесса для ДЗ: описание бизнес-процесса, разделение на три дорожки по ролям двух пользователей и выделенного сервиса при наличии. Действия должны соответствовать операциям пользователей в системе.

## Задание

Добавить авторизацию и возможность оформления заявок во фронтенд через Redux Toolkit, `redux-thunk`, кодогенерацию взаимодействия с API через Axios.

Добавить страницы регистрации и авторизации. Добавить страницу просмотра списка заявок пользователя в виде таблицы. Добавить в меню пункты для новых страниц.

Добавить в Redux Toolkit состояние интерфейса после авторизации. В приложении должно быть реализовано переключение между интерфейсом гостя и интерфейсом пользователя по кнопке Вход/Выход. После авторизации в меню должно отображаться имя или логин пользователя. При выходе должно сбрасываться содержимое конструктора новой заявки, а также фильтры пользователя.

Добавить на странице услуг кнопку добавления услуги в новую заявку. Добавить страницу заявки, где в статусе черновика можно удалить уже добавленные услуги, поменять их количество или подтвердить заявку. Эта же страница используется для просмотра старых заявок в других статусах, но без возможности редактирования.

Переход на страницу заявки выполняется через специальную кнопку, которая меняет состояние: если черновик есть, кнопка доступна; если заявки-черновика нет, кнопка отображается с другим стилем и недоступна.

Для обращений к методам веб-сервиса доменов заявка и м-м использовать axios, кодогенерацию и `redux-thunk` middleware. При выполнении запросов отображать на странице анимацию, блокирующую кнопки пользователя. Для запросов услуг и авторизации/регистрации использовать только axios.

Добавить интерфейс модератора, доступный после авторизации модератора:

- в списке заявок доступны кнопки смены статуса заявок;
- есть поля фильтрации по диапазону даты формирования и статусу заявок на стороне бэкенда;
- фильтрация по создателю заявки выполняется на фронтенде;
- список заявок работает через short polling для отображения актуальных статусов.

## Методические указания

- Redux Toolkit + fetch.
- Redux Toolkit + кодогенерация и Axios.
- Видео мастер-класс по внедрению Redux Toolkit и кодогенерации из Swagger.
